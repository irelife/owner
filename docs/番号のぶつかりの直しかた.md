## 2. 番号のぶつかり（`apiAsk` の1か所）

### 何が起きているか

```javascript
var no = 'C' + Utilities.formatDate(new Date(), 'Asia/Tokyo', 'yyyyMMdd') +
         '-' + (sh.getLastRow() + 1);
sh.appendRow([...]);
```

ふたりのオーナー様が**ほぼ同時**に送ると、どちらも「最終行」を同じ数として読み、
**同じ番号**になります。`やりとり` シートには**メールの列がなく**、
`msgsOf_` は番号だけで引くので、**別のオーナー様のやりとりが混ざって見えます。**

★ 書き込みは大丈夫です。`apiTalkMsg` は**メールと番号の両方**で確かめています。
　 混ざるのは**読むとき**だけです。

★ `askRows_`（`row`）と `workRows_`（`r._row`）は、その行の番号を使うので
　 いま重なりません。ただし**台帳の行を手で消すと行番号がずれて、
　 あとから同じ番号ができます。** 予防として同じ形に直しておきます。

### 貼るもの ①：`ext.gs` の末尾に足す

```javascript
/* ── 重ならない番号を作る ──────────────────────
 *  いままで： 'C' + 日付 + '-' + 行
 *            → ふたりがほぼ同時に送ると、同じ番号になりました。
 *  これから： うしろに8文字を足して、重ならないようにします。
 *
 *  ★8文字なのは、検査して決めました。6文字では 31の6乗＝8.8億通り。
 *    数のうえでは足りているように見えますが、20万回引くと17件重なりました
 *    （同じ誕生日の人が見つかりやすいのと同じ理由です）。
 *    8文字なら 8520億通りで、20万回引いても重なりは0件でした。
 *
 *  ★LockService は使いません。appendRow は行を取り合わないので、
 *    番号が重ならなくなれば、それで足ります。
 *    足すと、送信のたびに待ち時間が増えるだけです。
 *
 *  ★すでに入っている番号は、そのままで大丈夫です。
 *    形が変わるだけで、古い番号も今までどおり引けます。 */
function newNo_(prefix, n){
  var d = Utilities.formatDate(new Date(), 'Asia/Tokyo', 'yyyyMMdd');
  return prefix + d + '-' + (n || 0) + '-' + noRand_(8);
}

/* 重ならないための文字。
 * ★ 0 O 1 I l は入れません。お電話でお伝えするときに聞き分けられないためです。 */
function noRand_(n){
  var C = 'ABCDEFGHJKMNPQRSTUVWXYZ23456789';
  var s = '';
  for(var i = 0; i < n; i++){
    s += C.charAt(Math.floor(Math.random() * C.length));
  }
  return s;
}
```

★ 名前を `rand_` ではなく **`noRand_`** にしてあります。
　 `pass.gs` に `rand_` があるかもしれず、同じ名前の関数が2つあると
　 **あとに書いたほうだけが動く**ためです。探す手間をなくすため、
　 はじめから重ならない名前にしました。

### 貼るもの ②：3か所を差し替える

**`apiAsk` の中**

```javascript
/* 直す前 */
  var no = 'C' + Utilities.formatDate(new Date(), 'Asia/Tokyo', 'yyyyMMdd') +
           '-' + (sh.getLastRow() + 1);

/* 直した後 */
  var no = newNo_('C', sh.getLastRow() + 1);
```

**`askRows_` の中**

```javascript
/* 直す前 */
      no = 'C' + Utilities.formatDate(new Date(), 'Asia/Tokyo', 'yyyyMMdd') + '-' + row;

/* 直した後 */
      no = newNo_('C', row);
```

**`workRows_` の中**

```javascript
/* 直す前 */
      var id = 'W' + Utilities.formatDate(new Date(), 'Asia/Tokyo', 'yyyyMMdd') + '-' + r._row;

/* 直した後 */
      var id = newNo_('W', r._row);
```

## 3. `stReply` ── お知らせ先を、画面から受け取らない

### いま

```javascript
if(req.mail){
  MailApp.sendEmail({ to: String(req.mail), … });
}
```

`req.mail` を**そのまま**使っています。当社用の画面が送ってくる値なので、
ふだんは正しいのですが、**番号とアドレスがずれていても気づけません。**
担当者が一覧で選び間違えると、**別のオーナー様に「お返事を入れました」**が届きます。

また `askRows_().filter(...)[0]` は**最初に見つかった1件**だけを
「回答済み」にします。もし番号がぶつかっていたら、**別のオーナー様の行**を
「回答済み」にしてしまいます。

### 直した `stReply`（まるごと差し替え）

```javascript
function stReply(req){
  var id   = String(req.id || '');
  var body = String(req.body || '').slice(0, 4000);
  if(!id || !body.trim()) return ng_('番号と本文が要ります。');

  /* ★お知らせ先は、番号から引き直します。
   *   画面から送られてきたアドレスをそのまま使うと、
   *   選び間違いで別のオーナー様に届いてしまいます。 */
  var to = '';
  if(id.charAt(0) === 'C'){
    askRows_().forEach(function(x){
      if(x.no !== id) return;
      /* ★見つかった行は全部「回答済み」にします。1件だけにすると、
       *   番号がぶつかっていたときに、片方が確認中のまま残ります。 */
      askSheet_().getRange(x._row, 5).setValue('回答済み');
      to = String(x.mail || '');
    });
  }else{
    workRows_().forEach(function(r){
      if(String(r['番号']) === id) to = String(r['メール'] || '');
    });
  }
  if(!to) return ng_('その番号のオーナー様が、台帳に見つかりませんでした。');

  addMsg_(id, '当社', body);

  try{
    MailApp.sendEmail({
      to      : to,
      replyTo : prop_('SUPPORT'),
      subject : 'オーナーマイページに、お返事を入れました（IREライフ株式会社）',
      body    : 'いつも大変お世話になっております。IREライフ株式会社でございます。\n\n' +
                'マイページに、お返事を入れました。下記よりご確認くださいませ。\n\n' +
                '　' + prop_('SITE_URL') + '\n\n' +
                '─────────────────\nIREライフ株式会社\n' +
                prop_('SUPPORT') + '\n─────────────────'
    });
  }catch(err){ log_('stReply mail', err); }

  return { ok:true };
}
```

★ 順番も変えました。**台帳に見つからなければ、`addMsg_` もしません。**
　 いまは先に書き込んでいるので、番号を打ち間違えると
　 **誰のものでもないやりとりが `やりとり` シートに残ります。**

★ `staff.html` は直さなくて構いません。`req.mail` を送っても無視されるだけです。

## 4. 小さいもの（急ぎません）

| | 何 | どうなるか |
|---|---|---|
| 1 | `apiInsPut` の `INS_MAX` の数え | ほぼ同時に2件上げると、12件の上限を13件まで超えられます。害は小さいです |
| 2 | `やりとり` にメールの列がない | ご本人確認は「番号 → 問い合わせ・工事 → メール」とたどっています。列を足せばもっと確かになりますが、表の形が変わり、すでに入っているぶんは空のままになります |

## 5. 反映と確かめ

1. Apps Script で **保存**
2. **［デプロイを管理］→ 鉛筆 → 新バージョン**
   　★［新しいデプロイ］は押さないでください。URL が変わってアプリが止まります。
3. マイページの［お問い合わせ］から1件送る
4. `問い合わせ` シートの **番号** を見る
   　→ `C20260922-7-K4M9QXBT` のように、うしろに8文字が付いていれば直っています
5. **古い番号のお問い合わせも開く**
   　→ 中身が出れば、すでに入っている番号もそのまま使えています
6. 当社用の画面（`staff.html`）に、**わざと違う合言葉**で入ってみる
   　→ 「合言葉が違います。」と出ること。20回で止まり、SUPPORT にメールが来ること
7. 当社用の画面から**お返事を1件返す**
   　→ そのオーナー様に届くこと。状況が「回答済み」になること
