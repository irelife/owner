## 1. ★いちばん急ぐもの ── 当社用の入口に、足止めがありません

### 何が起きうるか

```
routeStaff_（stPing／stList／stReply／stArea）
  ↓
  入館証は要りません。req.key が ADMIN_KEY と合っていれば通ります
  ↓
  何回まちがえても、止まりません
```

いっぽう `stList` は、**支社を指定しなければ全オーナー様ぶん**を返します。

```
オーナー様のお名前・メールアドレス・お問い合わせの本文すべて（最大200件）
＋ 福山・倉敷・岡山・SUPPORT のアドレス
```

そして **Apps Script の住所は、秘密にできません。**
`js/config.js` に書いてあり、しかも**公開リポジトリ**です。
仮に隠しても、ブラウザの開発者ツールで誰でも見られます。画面から呼ぶ以上、避けられません。

つまり **「住所は誰でも分かる」＋「合言葉は何回でも試せる」** の組み合わせです。
オーナー様のログインには**5回で30分**の足止めがあるのに、
**当社用の入口にはありません。**

### 直しかた ── ①が本体、②は保険

**① `ADMIN_KEY` を、32文字以上の意味のない文字列に作り直す（これが本体）**

スクリプト プロパティで `ADMIN_KEY` を作り直してください。
短い言葉や、会社名・電話番号をもとにしたものであれば、いま変えてください。
下を Apps Script で実行すると、候補が出ます。

```javascript
/* 合言葉の候補を出します（実行ログに出るだけで、どこにも保存しません） */

    var s = '';
    for(var i = 0; i < 40; i++){
      s += C.charAt(Math.floor(Math.random() * C.length));

    Logger.log(s);
  }
  Logger.log('');
```

★ 40文字なら、総当たりは事実上できません。**①だけで、この穴はふさがります。**

**② 足止めを足す（保険）**

`ext.gs` の `routeStaff_` を、こう差し替えます。

```javascript
/* ★ 合言葉（ADMIN_KEY）で入る、当社用のもの。入館証は要りません */
function routeStaff_(action, req){
  var STAFF = ['stPing', 'stList', 'stReply', 'stArea'];
  if(STAFF.indexOf(String(action || '')) < 0) return null;
  if(!staffOk_(req)){
    return { ok:false, error:'auth', message:'合言葉が違います。' };
  }
  if(action === 'stPing')  return { ok:true };
  if(action === 'stList')  return stList(req);
  if(action === 'stReply') return stReply(req);
  if(action === 'stArea')  return stArea(req);
  return null;
}
```

そして末尾に、これを足します。

```javascript
/* ── 当社用の入口の足止め ──────────────────────
 *  いままで： 何回まちがえても止まりませんでした。
 *  これから： 20回続けてまちがえると、30分止めます。
 *            そのとき SUPPORT へお知らせのメールが飛びます。
 *
 *  ★これは保険です。本体は「ADMIN_KEY を長くすること」です。
 *  ★副作用： 嫌がらせで20回まちがえられると、当社も30分入れません。
 *    そのあいだ台帳は直接ひらけるので、仕事は止まりません。 */
var STAFF_MISS_ = 20;
var STAFF_LOCK_ = 30 * 60 * 1000;

function staffOk_(req){
  var c   = CacheService.getScriptCache();
  var now = new Date().getTime();

  var until = Number(c.get('staff_lock') || 0);
  if(until && now < until) return false;

  var key = String(prop_('ADMIN_KEY') || '');
  var got = String(req.key || '');

  /* ★合っていても、いなくても、同じだけ時間をかけてくらべます。
   *   「何文字目まで合っていたか」が返答の速さから分からないように
   *   するためです。 */
  var ok = (key.length > 0 && got.length === key.length);
  if(ok){
    var diff = 0;
    for(var i = 0; i < key.length; i++){
      diff |= (key.charCodeAt(i) ^ got.charCodeAt(i));
    }
    ok = (diff === 0);
  }

  if(ok){
    c.remove('staff_miss');
    c.remove('staff_lock');
    return true;
  }

  var miss = Number(c.get('staff_miss') || 0) + 1;
  if(miss >= STAFF_MISS_){
    c.put('staff_lock', String(now + STAFF_LOCK_), 21600);
    c.remove('staff_miss');
    try{
      MailApp.sendEmail({
        to      : prop_('SUPPORT'),
        subject : '【マイページ】当社用の画面で、合言葉の間違いが続きました',
        body    : '合言葉が' + STAFF_MISS_ + '回続けてまちがえられたため、\n' +
                  '30分のあいだ、当社用の画面を止めました。\n\n' +
                  '心当たりがない場合は、スクリプト プロパティの ADMIN_KEY を\n' +
                  'すぐに作り直してください（32文字以上の、意味のない文字列）。'
      });
    }catch(e){}
  }else{
    c.put('staff_miss', String(miss), 3600);
  }
  return false;
}
```

★ 長さが違うときは、くらべる前に外しています。**長さだけは分かります。**
　 ①（長い合言葉）を先にやっていれば、長さが分かっても総当たりはできません。

## 2. 番号のぶつかり（`apiAsk` の1か所）

### 何が起きているか

```javascript
var no = 'C' + Utilities.formatDate(new Date(), 'Asia/Tokyo', 'yyyyMMdd') +
         '-' + (sh.getLastRow() + 1);
sh.appendRow([...]);
```

ふたりのオーナー様が**ほぼ同時**に送ると、どちらも「最終行」を同じ数として読み、
**同じ番号**になります。`やりとり` シートには**メールの列がなく**、
`msgsOf_` は番号だけで引くので、**別のオーナー様のやりとりが混ざって見えます。**

★ 書き込みは大丈夫です。`apiTalkMsg` は**メールと番号の両方**で確かめています。
　 混ざるのは**読むとき**だけです。

★ `askRows_`（`row`）と `workRows_`（`r._row`）は、その行の番号を使うので
　 いま重なりません。ただし**台帳の行を手で消すと行番号がずれて、
　 あとから同じ番号ができます。** 予防として同じ形に直しておきます。

### 貼るもの ①：`ext.gs` の末尾に足す

```javascript
/* ── 重ならない番号を作る ──────────────────────
 *  いままで： 'C' + 日付 + '-' + 行
 *            → ふたりがほぼ同時に送ると、同じ番号になりました。
 *  これから： うしろに8文字を足して、重ならないようにします。
 *
 *  ★8文字なのは、検査して決めました。6文字では 31の6乗＝8.8億通り。
 *    数のうえでは足りているように見えますが、20万回引くと17件重なりました
 *    （同じ誕生日の人が見つかりやすいのと同じ理由です）。
 *    8文字なら 8520億通りで、20万回引いても重なりは0件でした。
 *
 *  ★LockService は使いません。appendRow は行を取り合わないので、
 *    番号が重ならなくなれば、それで足ります。
 *    足すと、送信のたびに待ち時間が増えるだけです。
 *
 *  ★すでに入っている番号は、そのままで大丈夫です。
 *    形が変わるだけで、古い番号も今までどおり引けます。 */
function newNo_(prefix, n){
  var d = Utilities.formatDate(new Date(), 'Asia/Tokyo', 'yyyyMMdd');
  return prefix + d + '-' + (n || 0) + '-' + rand_(8);
}

/* 重ならないための文字。
 * ★ 0 O 1 I l は入れません。お電話でお伝えするときに聞き分けられないためです。 */
function rand_(n){
  var C = 'ABCDEFGHJKMNPQRSTUVWXYZ23456789';
  var s = '';
  for(var i = 0; i < n; i++){
    s += C.charAt(Math.floor(Math.random() * C.length));
  }
  return s;
}
```

★ `rand_` は `ext.gs` にはありません（確認しました）。
　 ただし **`pass.gs` にあるかもしれません。** 先に `Ctrl`＋`F` で
　 `function rand_` を探してください。あれば `rand_` は足さず、`newNo_` だけ足します。
　 同じ名前の関数が2つあると、**あとに書いたほうだけが動きます。**

### 貼るもの ②：3か所を差し替える

**`apiAsk` の中**

```javascript
/* 直す前 */
  var no = 'C' + Utilities.formatDate(new Date(), 'Asia/Tokyo', 'yyyyMMdd') +
           '-' + (sh.getLastRow() + 1);

/* 直した後 */
  var no = newNo_('C', sh.getLastRow() + 1);
```

**`askRows_` の中**

```javascript
/* 直す前 */
      no = 'C' + Utilities.formatDate(new Date(), 'Asia/Tokyo', 'yyyyMMdd') + '-' + row;

/* 直した後 */
      no = newNo_('C', row);
```

**`workRows_` の中**

```javascript
/* 直す前 */
      var id = 'W' + Utilities.formatDate(new Date(), 'Asia/Tokyo', 'yyyyMMdd') + '-' + r._row;

/* 直した後 */
      var id = newNo_('W', r._row);
```

## 3. `stReply` ── お知らせ先を、画面から受け取らない

### いま

```javascript
if(req.mail){
  MailApp.sendEmail({ to: String(req.mail), … });
}
```

`req.mail` を**そのまま**使っています。当社用の画面が送ってくる値なので、
ふだんは正しいのですが、**番号とアドレスがずれていても気づけません。**
担当者が一覧で選び間違えると、**別のオーナー様に「お返事を入れました」**が届きます。

また `askRows_().filter(...)[0]` は**最初に見つかった1件**だけを
「回答済み」にします。もし番号がぶつかっていたら、**別のオーナー様の行**を
「回答済み」にしてしまいます。

### 直した `stReply`（まるごと差し替え）

```javascript
function stReply(req){
  var id   = String(req.id || '');
  var body = String(req.body || '').slice(0, 4000);
  if(!id || !body.trim()) return ng_('番号と本文が要ります。');

  /* ★お知らせ先は、番号から引き直します。
   *   画面から送られてきたアドレスをそのまま使うと、
   *   選び間違いで別のオーナー様に届いてしまいます。 */
  var to = '';
  if(id.charAt(0) === 'C'){
    askRows_().forEach(function(x){
      if(x.no !== id) return;
      /* ★見つかった行は全部「回答済み」にします。1件だけにすると、
       *   番号がぶつかっていたときに、片方が確認中のまま残ります。 */
      askSheet_().getRange(x._row, 5).setValue('回答済み');
      to = String(x.mail || '');
    });
  }else{
    workRows_().forEach(function(r){
      if(String(r['番号']) === id) to = String(r['メール'] || '');
    });
  }
  if(!to) return ng_('その番号のオーナー様が、台帳に見つかりませんでした。');

  addMsg_(id, '当社', body);

  try{
    MailApp.sendEmail({
      to      : to,
      replyTo : prop_('SUPPORT'),
      subject : 'オーナーマイページに、お返事を入れました（IREライフ株式会社）',
      body    : 'いつも大変お世話になっております。IREライフ株式会社でございます。\n\n' +
                'マイページに、お返事を入れました。下記よりご確認くださいませ。\n\n' +
                '　' + prop_('SITE_URL') + '\n\n' +
                '─────────────────\nIREライフ株式会社\n' +
                prop_('SUPPORT') + '\n─────────────────'
    });
  }catch(err){ log_('stReply mail', err); }

  return { ok:true };
}
```

★ 順番も変えました。**台帳に見つからなければ、`addMsg_` もしません。**
　 いまは先に書き込んでいるので、番号を打ち間違えると
　 **誰のものでもないやりとりが `やりとり` シートに残ります。**

★ `staff.html` は直さなくて構いません。`req.mail` を送っても無視されるだけです。

## 4. 小さいもの（急ぎません）

| | 何 | どうなるか |
|---|---|---|
| 1 | `apiInsPut` の `INS_MAX` の数え | ほぼ同時に2件上げると、12件の上限を13件まで超えられます。害は小さいです |
| 2 | `やりとり` にメールの列がない | ご本人確認は「番号 → 問い合わせ・工事 → メール」とたどっています。列を足せばもっと確かになりますが、表の形が変わり、すでに入っているぶんは空のままになります |
| 3 | `msgsOf_` が毎回 `やりとり` を全部読む | 数千件になると、返信のたびに1〜2秒かかります。`TextFinder` に変えれば速くなります |

## 5. 反映と確かめ

1. Apps Script で **保存**
2. **［デプロイを管理］→ 鉛筆 → 新バージョン**
   　★［新しいデプロイ］は押さないでください。URL が変わってアプリが止まります。
3. マイページの［お問い合わせ］から1件送る
4. `問い合わせ` シートの **番号** を見る
   　→ `C20260922-7-K4M9QXBT` のように、うしろに8文字が付いていれば直っています
5. **古い番号のお問い合わせも開く**
   　→ 中身が出れば、すでに入っている番号もそのまま使えています
6. 当社用の画面（`staff.html`）に、**わざと違う合言葉**で入ってみる
   　→ 「合言葉が違います。」と出ること。20回で止まり、SUPPORT にメールが来ること
7. 当社用の画面から**お返事を1件返す**
   　→ そのオーナー様に届くこと。状況が「回答済み」になること
