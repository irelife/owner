## 1. 支社ごとの問い合わせ先メール　★未設定（2026/9/19 に後日と決定）

### 決まっていること

オーナー様がマイページの「お問い合わせ」から送ったものを、
**その方の支社の担当者だけ**に届けます。返信すれば、オーナー様に直接返ります。

| スクリプト プロパティ | 届け先 |
|---|---|
| `MAIL_FUKUYAMA` | 福山 |
| `MAIL_KURASHIKI` | 倉敷・総社 |
| `MAIL_OKAYAMA` | 岡山 |
| `SUPPORT` | 上のどれにも当てはまらないときの受け皿 |

★ いまは `SUPPORT` だけ入っています。3つは空のままです。
　 **プロパティを足すだけで効きます。貼り直しもデプロイのやり直しも要りません。**

### 支社の決めかた（お決めいただいたとおり）

**住所で振り分けます。** PIVOT が物件の住所（`addr`）を持っているので、
物件名→支社の表を作る必要はありません。

```
PIVOT で［マイページへ送る］を押す
   ↓  そのオーナー様の物件の住所を見る
   倉敷市老松町・玉島乙島 → 福山   ← ★いちばん先に見ます
   岡山市                → 岡山
   倉敷市・総社市         → 倉敷
   福山市                → 福山
   ↓  支社をつけて送る
オーナー表の「支社」に入る
   ↓
問い合わせが、その支社のアドレスだけに届く
```

★ 並び順に意味があります。老松町・玉島乙島を先に見ないと、
　 どちらも倉敷市なので倉敷へ流れます。

**複数の支社に物件をお持ちのオーナー様は、物件の多いほうの支社に寄せます。**

### 実装する場所（3か所）

1. `2_tomypage-js`（PIVOT側・新規ファイル）
   　送る前に、そのオーナー様の物件の住所から支社を決めて `area` に入れる
2. `コード.gs` の `HEAD[SH.OWNER]` に `支社` を足す
   　`apiPush` が `o.area` を書き込む
3. `コード.gs` の `apiContact`
   　`prop_('SUPPORT')` → その方の支社のアドレス（無ければ `SUPPORT`）

**⑩（PIVOT2に［マイページへ送る］を足す）と一緒に入れます。**
先にやると、送る側と受ける側がちぐはぐになります。

### 決めていただくこと

- 福山・倉敷・岡山の、**それぞれの問い合わせ先アドレス**
- `SUPPORT`（受け皿）を、いまの `info@ire-life.com` のままにするか

## 4. `status` 窓口に `prop` と `room` を足す

入居状況を物件ごとにまとめました（2026/9/22）。いまは `place`
（「カルムコート東棟 201号室」）を画面側で切り分けています。

`status` が `prop` と `room` を別々に返すようにすれば、切り分けが不要になります。
**PIVOT2 はすでに `{kind, prop, room, date, note}` の形で送っており、
GAS が `place` に1本化しているだけです。**

```
コード.gs の apiStatus（入居状況を返すところ）
  → place のほかに prop と room も返す
```

画面側の直しは要りません。`prop` があればそちらを使う作りにしてあります。

**満室の物件を「満室です」と出すにも、GAS の足しが必要です。**
いまの `status` は 新規契約・解約予定・募集中 の3つだけを返すので、
満室の物件は1件も返ってきません（React 版は全部屋を返しています）。

## 8. 招待メール（2026/9/23 ご要望③）★設計だけ。着手前に確認が必要

### やりたいこと

PIVOT2 のオーナー一覧から、**マイページへの招待メール**を送れるようにする。

```
［招待する］を押す
   ↓
定型文 ＋ マイページのURL ＋ 初回のランダムパスワード を送る
「以後、明細はこちらからご確認ください」という案内を添える
   ↓
PIVOT2 側に「招待済み 2026/9/23」と出る（ボタンの色が変わる）
```

個別と一括（メール登録済みで、まだ招待していない方ぜんぶ）の両方。

### いま、どこまでできているか

**半分はすでに動いています。**［マイページへ送る］を押すと、
新しいオーナー様のアカウントが作られ、`pass.gs` が
初回パスワードのご案内メールを送ります（`PASS_SEND = true` のとき）。

**足りないのは3つです。**

| | 何が足りないか |
|---|---|
| 1 | **明細送信と切り離した「招待だけ」の窓口**がない |
| 2 | **誰を招待したかの記録**がない。オーナー表に列がない |
| 3 | 招待用の**定型文**がない（いまの文面は「初回パスワードのご案内」） |

### 設計（案）

**マイページ側（Apps Script）**

```
オーナー表に「招待日」の列を1つ足す（9列目）

stOwners（当社用・合言葉）
  返す … [{ mail, name, area, invited:'2026/9/23' または '' }]
  → PIVOT2 が「招待済み」を出すために使います

stInvite（当社用・合言葉）
  受ける … mails:[…]
  すること …
    ① アカウントが無ければ作る
    ② 初回パスワードを作り直す（pass.gs のやりかたをそのまま使う）
    ③ 招待の定型文＋URL＋パスワードを送る
    ④ 「招待日」に今日を入れる
  返す … 1件ずつの結果（送れた／アドレスが無い／失敗）
```

**PIVOT2 側**

```
オーナー一覧のタブに「招待」の列を足す
  未招待   … ［招待する］（差し色）
  招待済み … 「招待済み 2026/9/23」＋［もう一度送る］（控えめな色）
上に一括 … ［メール登録済みで未招待の N 名を招待する］
```

### ★着手する前に、必要なもの

**`pass.gs` と `コード.gs` をチャットに貼っていただく必要があります。**

理由は、**パスワードの作りかたを推測で書けない**からです。

- パスワードは `SHA-256(パスワード ＋ 塩 ＋ PEPPER)` で保存されています
- **混ぜかたを1文字でも違えると、オーナー様が入れなくなります**
- `pass.gs` の作りかたを**そのまま**使わなければなりません

`コード.gs` は、オーナー表の見出し（`HEAD[SH.OWNER]`）に列を足し、
`route()` に新しい窓口を登録するために必要です。

★ `pass.gs` は4関数だけなので、長くありません。

### 決めていただくこと

1. **招待の文面**を、どこで直せるようにするか
   　① PIVOT2 の「定型文」タブに増やす（当社で直せる）
   　② Apps Script のスクリプト プロパティに入れる
   　③ コードに書く（直すには私に頼む）
   　→ **①をおすすめします。**文面はこれから何度も直すはずです。
2. **「もう一度送る」を許すか。** 押すと**パスワードが変わります**。
   　前のパスワードでは入れなくなるので、ご本人に必ず届く形が要ります。
3. **一括のとき、何名まで一度に送るか。** Apps Script のメール送信には
   　1日あたりの上限があります（無料のアカウントで100通ほど）。
